# Technical decisions (extended study)

Each entry: what was decided, why, and where it is implemented. Numbers quoted here are filled in from
the final run (see `SUMMARY.md` for the complete figures).

## Phase 0 - environment and integrity

**D-01 - Pinned virtual environment instead of the system Python.** The system interpreter lacked matplotlib/seaborn/umap and `pip` could not write to it (permission errors, numpy upgrade attempt). `run_all.sh` creates `extension/.venv` from `requirements.txt` (numpy 1.26.4 as in the original environment, scikit-learn 1.5.2, pandas 2.2.3, scipy 1.14.1, pyarrow 19.0.1 - the last pyarrow line compatible with numpy 1.x). scikit-learn 1.5.2 still accepts `CalibratedClassifierCV(cv="prefit")`, which the calibration protocol uses (deprecated from 1.6). Implemented in `run_all.sh`, `requirements.txt`.

**D-02 - BOATOSBR is not regenerated.** The unified dataset contains 11 corpora, but the repository embeds only 10 (`ALL_DATASETS` in notebook 01 excludes BOATOSBR; its 3 404 rows exist only in the unified parquet). BOATOSBR is absent from every published table and from the 70/15/15 splits, and both studies are defined over "the 10 corpora of the per-dataset analysis". Regenerating its embeddings would add a corpus that was never split or benchmarked, so it was left out; the divergence is recorded in `results/sanity/integrity_report.md` and in `SUMMARY.md`. Implemented in `config.yaml` (`datasets_not_embedded`), `check_integrity.py`.

**D-03 - Train embeddings fetched with Git LFS, not regenerated.** The four `train_embeddings.npy` and `train_split.csv` were LFS pointer files locally. `git lfs pull --include=...` retrieved the originals (sha256 verified by LFS); shapes, dtypes, instance order and counts were then checked (`integrity_shapes.csv`, `integrity_counts.csv`). No embedding was recomputed, so the GPU was not used.

**D-04 - Hyper-parameters are taken from `classical_models_results.csv`.** The `best_params` column stores the Python dict of `GridSearchCV.best_params_` for all 32 pairs; no grid search had to be re-run. Parsed with `ast.literal_eval` (`common.load_best_params`).

**D-05 - Table 4 sanity check = refit on train+val with the saved parameters.** The original final models were refit on train+val before scoring the test split, so the reproduction does the same, then recomputes the mean per-corpus macro-F1 (`reproduce_table4.py`). Per-item agreement with the published predictions is also reported. Result (run of 2026-10-29): **PASS**, all 32 pairs within the 0.005 tolerance, max |diff| = 0.0023; 30 of the 32 pipelines reproduce the published test predictions *exactly* (100 % identical labels), the four kNN pipelines agree on 99.90 % of the test items (6 of 6 282 differ: distance-weighted votes with near-ties are sensitive to BLAS rounding) and Albertina-100M + LogReg on 99.98 % (1 item). In the clean verification run (D-25, GPU Gram matrix for the SVC) one further item of Albertina-900M + SVC-RBF flips (agreement 99.98 %, reproduced mean macro-F1 0.8220 instead of 0.8219), so 29 of 32 pipelines are then bit-identical to the published predictions; PASS in both runs. Details in `results/sanity/table4_reproduction.md` and `table4_prediction_agreement.csv`.

**D-06 - Macro-F1 definition.** `sklearn.metrics.f1_score(average="macro")`, i.e. macro over the union of labels present in truth and prediction - identical to the hand-written `macro_f1_score` of notebook 04 that produced the published per-dataset values. Per-class precision/recall are reported with `labels=[0,1]` and `zero_division=0`.

**D-07 - Parallelism does not change results.** Fits are distributed with joblib over (pipeline, hold-out) tasks; every estimator uses the original `random_state=42`. `RandomForestClassifier` receives `n_jobs=2` inside workers instead of `-1` (same trees: `n_jobs` only affects scheduling). BLAS threads are limited to 1 per worker. `config.yaml: n_jobs, rf_n_jobs`.

**D-24 - SVC-RBF Gram matrix on the GPU (same model, ~100x faster).** The GPU is used to accelerate the new results. libsvm's cost on 1 536-d embeddings is dominated by re-evaluating RBF kernel entries whenever its small cache misses, so `gpu_svc.GPUKernelSVC` computes the full training Gram matrix once on the GPU (PyTorch 2.11 + CUDA 12.8, float64, exact `exp(-gamma*||x-y||^2)` with sklearn's `gamma="scale"` rule) and hands it to `sklearn.svm.SVC(kernel="precomputed")`: identical optimisation problem, solver (SMO), C, gamma and tolerance. Prediction evaluates the kernel against the support vectors on the GPU and applies `dual_coef_ @ K + intercept_`, which is libsvm's own decision rule. Verified on real embeddings: same support-vector counts, max |decision difference| 2e-12, 100 % identical predictions versus `SVC(kernel="rbf")`, and 100 % agreement with the *published* test predictions of `bertimbau_base + svc_rbf` when refit on train+val. A 30 k x 1 536 fit takes ~18 s instead of ~30 min (in the full run: 40 LODO SVC fits in 31 min of GPU time, at most 70 s each, against 44 CPU-hours for the 40 gradient-boosting fits). The matrix needs n^2 x 8 bytes of host RAM (7-14 GB here), so GPU fits run one at a time in the main process while the other classifiers run in the CPU pool (`common.run_tasks`); the balanced LODO (<= 5 400 training rows) keeps the plain CPU SVC. Gradient boosting, random forest and the others have no GPU equivalent that preserves the published algorithm and stay on the CPU. `config.yaml: gpu.svc_rbf` (auto/true/false); without CUDA everything falls back to the CPU SVC with identical results.

## Study 1 - LODO

**D-08 - Hold-out test set = whole corpus (train+val+test).** None of its instances enters training, so all 41 873 instances are used across the ten folds. Training pool = the other nine corpora, all splits. Scaler fitted on the training pool only (inside the sklearn `Pipeline`, as in the original).

**D-09 - Balanced LODO sampling.** For each hold-out, every training corpus is sub-sampled to the size of the smallest training corpus (TRE300 = 300, or FNEWSSET = 600 when TRE300 is held out), stratified by class with largest-remainder rounding and at least one instance of each class present (`common.stratified_subsample`). Seeds 42-46 (`numpy.random.default_rng(seed)`); the same sub-sample is used for all four encoders and eight classifiers of a given (hold-out, seed) so that comparisons are paired. The sampling plan is written to `results/lodo/lodo_balanced_sampling_plan.csv`.

**D-10 - Statistics.** Friedman over the 32 pipelines with the 10 hold-outs as units, Wilcoxon signed-rank (two-sided, `zero_method="wilcox"`) of the best mean pipeline vs. the other 31, Holm-Bonferroni at alpha = 0.05 - the same code path as notebook 04 (`common.friedman_wilcoxon_holm`). For the balanced variant the unit value is the mean over the five seeds. With n = 10 paired units the smallest attainable two-sided exact p is 2/2^10 = 0.00195, so Holm over 31 comparisons can never reject (0.00195 x 31 = 0.06 > 0.05) - exactly the situation of the published Table 6. This is reported as a property of the design, not hidden. Outcome of the run: full LODO Friedman p = 0.43 (W = 0.10), balanced LODO p = 0.0015 (W = 0.19); 11 raw Wilcoxon p < 0.05 in each scenario, 0 of 31 rejected after Holm in both (smallest adjusted p 0.30 / 0.06).

**D-11 - In-distribution reference values are the published ones.** `lodo_vs_indist.csv` uses `test_macro_f1_by_dataset_model.csv` (published per-corpus test macro-F1), never the refit of D-05, so the published results are not altered. Rankings are compared with Spearman's rho at three levels (4 encoders, 32 pipelines, 10 corpora) and within each corpus.

**D-12 - Uncalibrated scores for SVMs.** `linearsvc`/`svc_rbf` have no `predict_proba`; the per-instance parquet stores `prob_real = sigmoid(decision_function)` flagged with `score_kind = sigmoid_of_decision_function`. This pseudo-probability is used only as the *raw* condition in Study 2 and as ranking score; it is never interpreted as calibrated.

## Study 2 - calibration and selective classification

**D-13 - Scenario (a) trains on the train split only.** The published final models were refit on train+val, so calibrating them on val would leak training data into the calibrator. Study 2 (a) therefore fits the pipeline on train, fits the calibrators on val (`cv="prefit"`), and evaluates on test. The accuracy/macro-F1 of these models are consequently those of the published *validation* configuration, slightly different from the published test row.

**D-14 - Scenario (b) uses an 85/15 split of the training pool.** For each hold-out, a stratified (corpus x label) 15 % slice of the nine training corpora is reserved for the calibrators (`train_test_split(..., stratify=..., random_state=42)`); the model is trained on the remaining 85 %. The raw predictions of scenario (b) therefore differ slightly from Study 1 (which trains on 100 % of the pool); the held-out corpus never touches training or calibration.

**D-15 - "Raw" condition.** LogReg: `predict_proba`. SVC-RBF: logistic squash of the signed decision function (D-12). `SVC(probability=True)` was *not* used because it is itself a Platt scaling fitted by internal CV on training data, i.e. not a raw score. The sigmoid condition is exactly the `CalibratedClassifierCV(method="sigmoid", cv="prefit")` of the calibration protocol; isotonic uses `method="isotonic"`.

**D-16 - Predicted label under every condition = `P(REAL) >= 0.5`.** Calibrated conditions may flip a few decisions relative to the raw model when the calibrator moves the 0.5 crossing; coverage/F1 curves are computed from the calibrated decision so that each condition is internally consistent.

**D-17 - Calibration metrics.** Confidence `c = max(p, 1-p)`; ECE with 15 equal-width bins on [0.5, 1]; adaptive ECE with 15 equal-mass bins (`np.array_split` of the confidence ranking); MCE = largest bin gap (equal-width bins); Brier on P(REAL); log-loss with probabilities clipped to [1e-15, 1-1e-15].

**D-18 - Selective classification.** Thresholds 0.50-0.99 step 0.01 (50 values); an item is automatically classified when `c >= tau`; coverage = fraction covered; macro-F1 and accuracy on covered items; fraction routed to humans = 1 - coverage; selective risk = error rate on covered items. AURC follows Geifman et al. (mean of the risk over all coverage levels obtained by sorting items by decreasing confidence); E-AURC subtracts the AURC of the optimal ordering. The "minimum threshold" for a target is the smallest grid threshold whose covered macro-F1 reaches the target *with at least 30 covered items* (`calibration.min_covered`; without this floor a threshold covering a single correct item would count as "macro-F1 >= 0.95"); "not reached" when no threshold <= 0.99 does. Bootstrap: 1 000 resamples of the evaluation items (seed 42), percentile 95 % CI of the coverage (and of the threshold) attained in each resample; the fraction of resamples reaching the target is also stored. The per-threshold metrics are computed from cumulative confusion counts over confidence bins, which was verified to match scikit-learn exactly.

**D-19 - "ALL" aggregate.** Per-corpus rows plus an `ALL` row pooling every evaluation item of the scenario. Under LODO, `ALL` pools predictions coming from ten different models (one per hold-out), which is the operational view of a tool that must handle text from an unseen source.

## Error analysis

**D-20 - Probability source for the best LODO pipeline.** If the best pipeline by mean LODO macro-F1 is one of the four Study 2 pipelines, the *sigmoid-calibrated LODO* probabilities of scenario (b) are used (thresholds like 0.90 are meaningful only for calibrated probabilities); otherwise the script falls back to the Study 1 `predict_proba` scores. The choice is recorded in `results/errors/best_pipeline.json`. **Outcome:** the best LODO pipeline is Albertina-100M + kNN (7 distance-weighted neighbours), which is *not* a Study 2 pipeline, so the fallback applies: "confidence" is the distance-weighted vote fraction, and confidence >= 0.90 is in practice a unanimous neighbourhood (42.9 % of the items have confidence exactly 1.0, 43.2 % have >= 0.90). Study 2 was not re-run for kNN because its vote fractions are not a score that Platt/isotonic maps are meant for and the Study 2 pipelines were fixed in the study design; the same high-confidence analysis is reported for the calibrated SVC-RBF/LogReg LODO probabilities in `SUMMARY.md` (finding 9) and leads to the same conclusion.

**D-21 - UMAP settings = the published "2d_balanced" preset.** L2 normalisation, PCA to 50 components, UMAP (cosine, `n_neighbors=40` for a large encoder, `min_dist=0.10`, `spread=1.0`, seed 42) on all 41 873 instances of the best encoder.

**D-25 - Verification run.** After the first complete run (2026-10-29, outputs backed up outside the repository), `bash extension/run_all.sh --clean` was executed in place: `--clean` deletes `results/`, `figures/`, `tables/` and `logs/` (the per-task cache included) and rebuilds everything from the published embeddings. The repository has no other writable location (nothing outside `extension/` may change), so "a clean directory" means the cleaned `extension/` tree; the first-run CSVs were then compared with the rebuilt ones. **Outcome (2026-10-30, exit code 0, 14.9 h):** all 30 result CSVs have the same shape and columns; 15 are bit-identical and the other 15 differ only through two single predictions: 1 of 1 339 936 LODO predictions (BERTimbau-base + SVC-RBF, FAKETRUEBR held out, macro-F1 0.26424 -> 0.26449) and 1 of 200 992 Table 4 refit predictions (Albertina-900M + SVC-RBF), both SVC decision values within floating-point noise of zero (the GPU Gram matrix is computed in a different summation order; |decision diff| ~ 1e-12). Largest resulting change in any table: 2.8e-4 in `lodo_balanced_summary.csv` (delta column of that one cell), 2.5e-5 in the pipeline ranking (rank unchanged), 7.7e-6 in AURC; Friedman/Wilcoxon/Holm outputs, rankings, triage thresholds, calibration metrics, error lists and `best_pipeline.json` are identical. The only visible difference is the UMAP layout in `umap_coordinates.csv` and the two UMAP figures: umap-learn 0.5.7 is not bit-reproducible across runs even with `random_state` set (parallel NN-descent), the global arrangement is the same (r = 0.96 after optimal rotation) and the corpus/outcome columns are identical, so the figure changes only in orientation and fine detail. The outputs now in `results/`, `tables/` and `figures/` are those of the verification run.

**D-26 - Label convention of the published per-sample analysis.** The split files, the embeddings metadata and every script of this extension use `label_id` 0 = FAKE, 1 = REAL (`codes/results/splits/*.csv`, column `label`). The published analysis script `codes/model_results_stat_analysis.py`, however, mapped the classical pipelines' raw ids as 0 -> REAL, 1 -> FAKE when it built `codes/results/analysis_outputs_models/test/*`, while the zero-shot rows (whose answers are the strings REAL/FAKE) kept the correct names. Consequences, verified on `test_standardized_predictions_per_sample.csv`: the classical rows disagree with the split labels on 100 % of the items, the zero-shot rows agree on 100 %; every *symmetric* quantity in those files is unaffected (accuracy, macro-F1, MCC, bootstrap CIs of those metrics, McNemar, Pearson correctness, agreement counts, Friedman/Wilcoxon tables, Table 4), but the per-class columns of the classical models (`fake_*`/`real_*`, `TP/TN/FP/FN`, `support_fake/real`) are swapped, so a classical-vs-LLM comparison of per-class metrics taken from those files would be inconsistent. `make_baseline_figures.py` therefore rebuilds the class names of the classical rows from `y_true_raw`/`y_pred_raw` with the split convention and recomputes the per-model report (`recompute_report`, with an assertion that accuracy and macro-F1 match the published values to 1e-9). The published files are not modified. Two further properties of the zero-shot runs are made explicit in the figures: they cover 5 765 of the 6 281 test items (no COVID19BR item and 156 FACTCKBR items are missing), and 14 answers are undefined (refusals or non-label text) and excluded.

**D-27 - Baseline figure set in English.** Every plot, chart and analysis of the report, including those of the published results, is provided in English at report quality. The original figures under `codes/results` (Portuguese titles such as "Accuracy com IC bootstrap", raw model identifiers, "Label 0/1" legends, overlapping annotations) cannot be edited (nothing outside `extension/` changes), so `make_baseline_figures.py` redraws the whole published analysis from the read-only CSV/NPY files into `figures/baseline/` and `tables/baseline/` with the conventions of `make_figures.py`, and adds analyses that the raw files support but the original figures did not show (per-corpus macro-F1 of all 42 models, the 42 x 42 McNemar and correctness-correlation matrices with Holm correction over the 861 pairs, encoder rank within classifier, zero-shot label bias and refusals, hard examples, UMAP per split). The UMAPs reuse the settings of `config.yaml: errors.umap` on the published test/validation/train embeddings; like all umap-learn layouts they are reproducible only up to orientation (D-25). The Markov-like transition file of the published analysis is not redrawn: it covers an arbitrary chain of model pairs and the same information is contained in the McNemar matrix. `FIGURES.md` indexes both sets with captions.

## Figures and tables

**D-22 - Colour conventions.** Fixed, colour-blind-validated categorical order (encoders: blue/orange/aqua/yellow; conditions raw/sigmoid/isotonic: blue/orange/aqua; scenarios: in-distribution blue, LODO orange); single-hue blue ramp for the heatmap; blue-grey-red diverging map for deltas. Ten corpora in a single scatter exceed what can be made fully colour-blind-safe, so the UMAP figure is complemented by a small-multiples version with one corpus per panel. Fonts 8 pt, widths 3.5 in (one column) / 7.2 in (two columns), PDF + PNG 300 dpi.

**D-23 - LaTeX tables.** `booktabs`, complete `table`/`table*` environments with captions and labels, generated by `make_tables.py`; no manual editing. Cells that cannot be computed are marked `--` and explained in the caption ("not reached").
